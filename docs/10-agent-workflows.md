# Agent 工作流

这六项功能由同一批次交付。日常开发在 `dev` 验证与部署；本文不代表已打版本标签或发布桌面安装包。

## 限时、限范围授权

1. 把要分享的知识库标为“与对方 Agent 共享”。
2. 在设置 → 安全 → Agent 限时授权，选择联系人、共享知识库和有效期（1–720 小时）。填写对方真正签名的 DID：Confer 通常用联系人所有者 DID（不含末尾的 `:agent`）。
3. 凭据只显示一次。通过安全通道交给对方，对方在联系人详情中保存。网关使用 AES-256-GCM 加密保存，不把保存后的凭据返回客户端。
4. 对方发起咨询时自动携带 `X-Confer-Capability`。该请求头也必须被 RFC 9421 签名覆盖；原生和 HTTP+JSON 两种 A2A binding 都适用。
5. 发出第一份授权后，该联系人每次提问必须携带有效令牌；省略、到期或撤销不能恢复旧的宽泛访问。未使用过此功能的联系人保留原有策略行为。

接收方签发高熵不透明凭据，数据库仅保存 SHA-256。权限以接收方、联系人、验证过的签名者、知识库列表和有效期为界，不是可转授的 macaroon，也不是仅靠提示词分类的主题白名单。它只收窄既有共享范围，不越过联系人同意、策略和人工批准。对方无法访问所有者私有记忆；受限回合不读取过去可能更宽范围的回答、不启用网络搜索。恢复等待批准的问题及回答交付前会重新检查授权。取消知识库共享也会生效。

撤销在设置中操作。旧的已交付内容无法收回。每份授权适用于该所有者的 Agent，当前没有按 Agent 子账号或单文档的独立授权。

## 委托进度与人工接管

聊天右下角“委托任务”可创建任务或打开任务页 `/tasks`。任务页显示状态、决策卡和最近 100 条持久事件，可以记录联系谁、等待什么、补充资料，以及完成或取消任务。

状态为：进行中、等待对方、等待补充、人工接管、已完成、已取消。进度由所有者或被授权的管理操作员明确提交；创建任务本身不会自动联系别人，也不会假报执行进度。操作员通过 `POST /api/v1/errands/:id/progress` 写入状态与说明。

人工接管、取消，以及接管后的恢复仅允许已登录所有者操作。接管或终止后不能继续推送或批准决策卡，浮动待办也不再显示这些卡。卡片审批与接管使用同一任务行锁，不能并发绕过；个人 API 凭据永远不能代替本人批准决策。

## 项目 Markdown 同步

Codex 和 Claude 共用项目根目录 `.confer/project.json`，不包含任何凭据：

```json
{
  "gatewayUrl": "http://localhost",
  "projectId": "my-project"
}
```

环境变量 `CONFER_GATEWAY_URL`、`CONFER_PROJECT_ID` 优先。从项目根目录启动 MCP，使用 `sync_project_memory(peerId, direction)`：

- `pull`：从一个原子服务端快照下载 `facts.md`、`decisions.md` 到 `.confer/peers/<peerId>/`。
- 在编辑器中查看、修改 Markdown；可将这两个文件与非秘密的项目配置提交进 Git。
- `push`：按上次同步版本提交两份 Markdown。服务端使用 compare-and-swap，版本变化返回 `409 sync_conflict`。

本地 `.sync.json` 记录实例、实际认证账号 ID、项目、对方及内容哈希，已加入 `.gitignore`。本地修改、未跟踪的同名文件、账号/实例切换或符号链接都会阻止覆盖。已有的 `read_project_memory` / `write_project_memory` 仍可使用；写入后需要重新同步。

冲突处理：先把本地 Markdown 另存为备份，用 `read_project_memory` 检查远端；移走待合并的本地两份文件后 `pull`，将备份中的修改合并到新文件，再 `push`。不存在自动覆盖或自动合并。此功能同步已有的项目事实与决策，不会把所有咨询内容擅自写进项目。

## 开发工具账号绑定

在仓库根目录运行：

```bash
bun run packages/mcp-a2a/src/server.ts --login --gateway http://localhost
```

已安装的插件可用 `node <插件路径>/dist/server.mjs --login --gateway https://你的实例`。传入浏览器访问的实例源地址；不要使用只提供 API 的开发端口（开发时客户端通常在 `:1420`）。远程实例必须 HTTPS，只有 loopback 允许 HTTP。

命令打开浏览器并显示设备验证码；在已登录的浏览器核对码、工具名称、账号和访问范围，再明确批准。10 分钟到期，只允许兑换一次；拒绝、到期或重复兑换失败。取得的个人 API 凭据 90 天到期，可在设置 → 安全撤销。它具有普通个人 API 访问能力，可读写所有者数据；没有安全管理、管理员权限或审批权限。不是仅针对咨询的细粒度 OAuth scope。

凭据保存于 macOS Keychain、Linux Secret Service（需安装 `secret-tool` 并解锁 keyring）或 Windows 当前用户的 DPAPI 加密存储。项目文件、插件配置和日志中不保存明文凭据。重启 MCP 后自动按实例读取。也可通过 `CONFER_API_TOKEN` 显式注入个人凭据；原先用户名/密码环境变量方式保持兼容。

macOS Keychain 的实际读写已验证；Linux/Windows 的原生存储需要在相应平台现场验收。MCP SDK 的真实 stdio 握手、严格工具 schema、设备凭据访问和 Markdown 同步已纳入测试。

## 回答依据与纠错

- 回答的来源可展开查看摘录。跨实例回复可携带最多 10 条来源（每段最多 4000 字符），标为“未验证”，不带对方内部文档/知识库 ID；签名只能证明发送者，不能证明资料本身正确。
- 回答旁“反馈问题”可报告回答错误、记忆错误或资料过期。反馈归当前账号，可在设置 → 安全查看；单独提交反馈不会重新训练模型。
- 记忆页“纠正记忆”修改文本并重新索引，保留原始来源标记，后续检索使用新内容。
- 自有资料的引用有“排除过期资料”操作，成功前会等待 Qdrant 删除完成。原文件和文档记录保留，状态为 `outdated`；可以在知识库中重试索引恢复。对方发来的资料不能借此操作修改。

## 可体验的演示 Agent

登录页的“体验演示 Agent”进入 `/demo`，无需账号、模型密钥或第二位用户。使用虚构 X100 手册，演示添加联系人、两分钟限定授权、技术问答与出处、拒绝私人数据、显式采购批准和撤销。它是明确标记的离线交互演示，不是实际下单或真实跨实例通信。

原始资料在 `packages/client/public/examples/x100-manual.md`。实际协议链路也有独立可复现演练，使用正常注册的两个账号、真实 HTTP 签名、隔离数据库/Qdrant/对象存储和 mock LLM/embedding：

```bash
bun run test:setup
bun run --filter @confer/gateway test src/routes/demo-peer.integration.test.ts
```

该演练覆盖互加联系人、上传和索引手册、签发/保存授权、咨询/回复及来源传递、反馈、排除后的实际检索和撤销后的拒绝，不会使用生产账号或真实模型密钥。公开的长期在线 demo peer 需要单独的域名、托管环境和运维配置。
