# Confer — उत्पाद की परिभाषा

## एक वाक्य में

**Confer एक प्रोटोकॉल और प्लेटफ़ॉर्म है जिस पर AI Agents अपने मालिकों की ओर से आपस में बात करते हैं।** हर उपयोगकर्ता या कंपनी अपना खुद का AI Agent चलाती है, जो उसका ज्ञान, उसके दस्तावेज़ और उसकी सेवा-क्षमता साथ लिए चलता है; उपयोगकर्ता दूसरों के Agents से अपने Agent के ज़रिए बात करता है — जानकारी पाने, काम बाँटने और काम पूरा करने के लिए।

## हम कौन-सी समस्या हल करते हैं

### असली तकलीफ़

ज्ञान दस्तावेज़ों में बंद पड़ा है, और जिसे उसकी ज़रूरत है वह वही नहीं है जो उसे समझता है:

- **B2B**: किसी और का हार्डवेयर, SDK या सेवा जोड़ने के लिए डेवलपर को हज़ारों पन्नों के PDF, Word और वेब दस्तावेज़ खंगालने पड़ते हैं। वेंडर सपोर्ट देर से जवाब देता है, दूसरे टाइम ज़ोन में बैठा है, और हमेशा सही भी नहीं होता। Claude Code जैसे AI कोडिंग टूल "बहुत लंबा दस्तावेज़ + वेंडर का अपना ज्ञान" वाले इस मेल को ठीक से नहीं संभाल पाते।
- **B2C**: कोई सेवा ढूँढ़नी हो (रेस्तराँ, मरम्मत, घरेलू काम, डॉक्टर) तो या तो फ़ोन करना पड़ता है या अंधेरे में खोजना पड़ता है। और दोस्त ऑफ़लाइन या व्यस्त हो तो उस तक पहुँचने का रास्ता ही नहीं बचता।

### मौजूदा हलों की सीमाएँ

| हल | कमी |
|---|---|
| आम ChatGPT/Claude | वेंडर का अपना ज्ञान नहीं है; दस्तावेज़ RAG में डाल भी दें तो मिलान सतही ही रहता है |
| वेंडर का सपोर्ट | धीमा, महँगा, बढ़ाया नहीं जा सकता, रात में कोई नहीं होता |
| दूसरे इंजीनियर को फ़ोन करना | टाइम ज़ोन, भाषा और उपलब्धता आपके बस में नहीं |
| ईमेल का आना-जाना | इंतज़ार लंबा, और कुछ भी समानांतर में नहीं चलता |

### Confer की मूल परिकल्पना

**जिसके पास विशेषज्ञ ज्ञान या सेवा-क्षमता है, वह खुद को एक "बाहर की ओर जवाब देने वाले Agent" में पैक कर ले, और जिसे वह ज्ञान चाहिए वह अपने Agent के ज़रिए पूछे।** दोनों में से किसी को दूसरे के दस्तावेज़ नहीं पढ़ने पड़ते; विशेषज्ञ ज्ञान वहीं से जवाब देता है जहाँ वह रहता है, और बातचीत असिंक्रोनस चलती रहती है।

## लक्षित उपयोगकर्ता

### पहला चरण (MVP): B2B डेवलपर

- **प्रोफ़ाइल**: हार्डवेयर इंटीग्रेशन, तीसरे पक्ष के SDK को जोड़ने, या एंटरप्राइज़ सिस्टम आपस में जोड़ने वाले डेवलपर — खासकर छोटी और मँझोली टीमों के फुल-स्टैक और बैकएंड इंजीनियर।
- **आम तकलीफ़**: वेंडर के दस्तावेज़ खराब हैं; तकनीकी सहायता देर से आती है; वेंडर-विशिष्ट जानकारी न होने पर Claude Code बार-बार गलत हो जाता है।
- **फ़ैसले का हक़**: डेवलपर अपने औज़ार खुद चुनता है (MCP प्लगइन लगाने के लिए बॉस से मंज़ूरी नहीं चाहिए)।

### दूसरा चरण: B2B कंपनियाँ

- वे कंपनियाँ जो अपने ग्राहकों और साझेदारों को AI सहायता की खिड़की देना चाहती हैं (खासकर औद्योगिक उपकरण निर्माता, SaaS कंपनियाँ और डेवलपर-टूल कंपनियाँ)।
- वे मँझोली और बड़ी कंपनियाँ जो चाहती हैं कि कर्मचारी एक साझा एंटरप्राइज़ Agent नेटवर्क के ज़रिए मिलकर काम करें।

### तीसरा चरण: B2C व्यक्ति

- आम उपयोगकर्ता जो चाहते हैं कि उनका "AI प्रतिनिधि" रोज़मर्रा के काम संभाले (किसी से मिलने का तय करना, सेवा ढूँढ़ना, दोस्त से पूछना)।
- अनौपचारिक बातचीत के मौके।

## मूल्य प्रस्ताव

| उपयोगकर्ता | मूल्य |
|---|---|
| डेवलपर | Claude Code से कोड लिखते समय वेंडर-विशिष्ट सवाल आने पर वेंडर के Agent से अपने-आप पूछ लिया जाता है और संदर्भ-सहित जवाब आता है — दस्तावेज़ पढ़ना खत्म |
| वेंडर | अपने दस्तावेज़ों को एक सार्वजनिक Agent में बदल देता है, तकनीकी सहायता की कार्यक्षमता दस गुना करता है और ग्राहक संतुष्टि बढ़ाता है |
| कंपनी | भीतर और बाहर का संवाद एक Agent नेटवर्क में एक साथ, ज्ञान जमा होता जाता है, और भाषाओं के आर-पार सहयोग होता है |
| व्यक्ति | आप न हों तो AI जवाब दे देता है, और दोस्तों के बीच के काम आधे-अपने-आप तय हो जाते हैं |

## मुख्य परिदृश्य (शुरू से अंत तक 4 कहानियाँ)

### परिदृश्य 1: डेवलपर Claude Code से हार्डवेयर जोड़ता है (MVP का केंद्रीय परिदृश्य)

लाओ वांग Claude Code से ABC Industries के X100 उपकरण के लिए Modbus इंटीग्रेशन बना रहा है।

1. लाओ वांग Claude Code से कहता है: "X100 के लिए Modbus से तापमान पढ़ना लिखो, 4 चैनल एक साथ।"
2. Claude Code भाँप लेता है कि यह ABC Industries का उपकरण है और ABC का Agent इस प्रोजेक्ट में पहले से दर्ज है।
3. Claude Code `agent_network.ask_peer(peer="abc-industries", question="X100 के तापमान रजिस्टर और सुझाया गया फ़ंक्शन कोड?")` बुलाता है।
4. ABC का Agent सवाल पाता है, अपने साथ जुड़ी मैनुअल v3.2 में खोजता है, "तापमान रजिस्टर 0x40-0x47, सुझाया गया फ़ंक्शन कोड 0x03" पाता है, और स्रोत पृष्ठ संख्या समेत लौटा देता है।
5. जवाब अपने-आप `.claude/peers/abc-industries/facts.md` में जमा हो जाता है।
6. Claude Code इसी सत्यापित तथ्य के आधार पर कोड लिखता है।
7. लाओ वांग को PR के लिए तैयार कोड मिलता है, जिसमें हर अहम फ़ैसले के पीछे एक संदर्भ है।

**जो तकलीफ़ें मिट जाती हैं**: लाओ वांग को PDF खोलनी नहीं पड़ती; Claude Code को अंदाज़ा नहीं लगाना पड़ता; जवाब वेंडर का है इसलिए प्रामाणिक है; और अगली बार ऐसा ही कोड लिखते समय जमा हुआ ज्ञान अपने-आप काम आ जाता है।

### परिदृश्य 2: B2B मैसेजिंग में कई Agents का साथ काम करना

कंपनी में एक "Modbus इंटीग्रेशन" प्रोजेक्ट ग्रुप है जिसमें 3 इंजीनियर + ABC Industries का Agent + कंपनी का अंदरूनी SDK Agent हैं।

1. इंजीनियर शियाओ ली ग्रुप में ABC Agent को टैग करता है: "RTU मोड में X100 की वोल्टेज सीमा क्या है?"
2. ABC Agent जवाब देता है: "24V DC, इंस्टॉलेशन मैनुअल पृष्ठ 12 के अनुसार।"
3. इंजीनियर शियाओ वांग जवाब देखकर अंदरूनी SDK Agent को टैग करता है: "क्या यह हमारी PowerSupply लाइब्रेरी के साथ चलेगा?"
4. अंदरूनी SDK Agent अंदरूनी विकी का हवाला देकर कहता है: "चलेगा, पर `safe_mode=True` लगाना होगा।"
5. पूरी बातचीत अपने-आप एक थ्रेड के रूप में सहेज ली जाती है, और अगली बार ऐसा ही सवाल उठे तो उसी थ्रेड का हवाला दिया जा सकता है।

### परिदृश्य 3: B2C में दोस्त की ओर से जवाब देना (आधा स्वचालित)

शियाओ झांग सप्ताहांत में लाओ ली को पहाड़ चढ़ने बुलाना चाहता है। लाओ ली मीटिंग में है, उसका AI इस तरह सेट है: "कार्यक्रम से जुड़े सवालों का जवाब मेरी ओर से दे दो, बाकी रोक रखो।"

1. शियाओ झांग Confer पर लाओ ली को संदेश भेजता है: "शनिवार सुबह पहाड़ चलें?"
2. लाओ ली का Agent कैलेंडर देखता है: शनिवार सुबह खाली है, दोपहर बच्चों के साथ है।
3. Agent शियाओ झांग को जवाब देता है: "शनिवार सुबह खाली है, पर दोपहर में बच्चों को ले जाना है। जल्दी निकलें और 2 बजे से पहले लौट आएँ, यही ठीक रहेगा।"
4. मीटिंग खत्म होने पर लाओ ली देखता है कि उसके Agent ने उसकी ओर से क्या कहा, और उसमें जोड़ या बदल सकता है।

### परिदृश्य 4: दूसरे देश और दूसरी भाषा के वेंडर के साथ तालमेल

चीनी इंजीनियर शियाओ चेन जर्मनी के Vendor X के औद्योगिक उपकरणों पर काम कर रहा है।

1. शियाओ चेन चीनी में पूछता है: "X उपकरण 100ms में कितने चैनल पढ़ सकता है?"
2. चीनी सवाल जर्मन में अनूदित होकर Vendor X के जर्मन-भाषी Agent को भेजा जाता है।
3. जर्मन-भाषी Agent अपनी ही जर्मन मैनुअल का हवाला देकर कहता है: "128 चैनल, पृष्ठ 45।"
4. जवाब शियाओ चेन के लिए वापस चीनी में अनूदित होता है; उद्धृत हिस्सा मूल जर्मन पाठ के साथ चीनी टिप्पणी समेत रहता है, और क्लिक करने पर मूल पृष्ठ खुल जाता है।

## जो हम नहीं करेंगे

Confer स्पष्ट रूप से यह **नहीं** करता:

- ❌ अपने बड़े मॉडल प्रशिक्षित करना (OpenAI / Anthropic / DeepSeek आदि की API इस्तेमाल होती है)
- ❌ Slack या Feishu की जगह पूरा एंटरप्राइज़ मैसेंजर बनना (हमारा ध्यान Agents के सहयोग पर है; आम चैट साथ में मिल जाती है)
- ❌ Claude Code की जगह लेना (हम उसके सहयोगी हैं, प्रतिद्वंद्वी नहीं)
- ❌ अपनी भुगतान, अनुबंध या कानूनी व्यवस्था बनाना (यह पहले से मौजूद SaaS का काम है)
- ❌ सार्वजनिक "AI सोशल नेटवर्क" बनाना (वह रूप जिसमें Agents आपस में ही खेलते रहते हैं, Moltbook जैसा)

## रणनीतिक समझ

**Claude Code के साथ एकीकरण ही कोल्ड स्टार्ट का रास्ता है।** डेवलपर समुदाय की क्रय-शक्ति ज़्यादा है, फ़ैसले तेज़ हैं, और अपनाना एकतरफ़ा है — एक MCP प्लगइन लगाया और इस्तेमाल शुरू। पहले हम डेवलपरों को खींचते हैं, फिर उनकी कंपनियों तक पहुँचते हैं, फिर उन कंपनियों के वेंडरों से अपना सार्वजनिक Agent तैनात करवाते हैं। यह **ग्राहक की ओर से उल्टी दिशा में आपूर्ति-पक्ष तक फैलने का रास्ता** है, और परंपरागत "पहले B2B फिर B2C" या उसके उलट से ज़्यादा व्यवहार्य है।
