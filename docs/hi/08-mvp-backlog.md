# Confer — MVP का रोडमैप और बाक़ी काम

milestone के हिसाब से टुकड़े; हर milestone एक ऐसा संस्करण है जो सौंपा और दिखाया जा सके।

## v0.1 — Core proof of concept (4-6 सप्ताह)

**लक्ष्य**: एक ही मशीन पर «उपयोगकर्ता ↔ अपना Agent ↔ सामने वाला Agent» की पूरी शृंखला चल जाए।

**दायरा (अनिवार्य)**

- [x] बैकएंड: gateway + agent runtime + conversation + identity (चार सेवाएँ; एक ही प्रक्रिया में हों या अलग-अलग, दोनों चलेगा)
- [x] PostgreSQL का schema (देखें 04-data-model.md), migration औज़ार से सँभाला हुआ
- [x] उपयोगकर्ता का पंजीकरण / लॉगिन (केवल पासवर्ड काफ़ी है; OAuth या passkey नहीं)
- [x] DID:web दस्तावेज़ बनाना और उजागर करना (`/.well-known/did.json`)
- [x] AgentFacts दस्तावेज़ बनाना और उजागर करना
- [ ] A2A प्रोटोकॉल — भीतर आना और बाहर जाना (HTTP हस्ताक्षर की जाँच + capability token की जाँच)
- [x] agent runtime: LLM बुलाने का चक्र (फ़िलहाल सिर्फ़ दो प्रदाता — Claude और DeepSeek)
- [x] सरल नीति-इंजन: श्वेतसूची वाले peer, और या तो सब स्वीकृत या सब अस्वीकृत
- [x] क्लाइंट: एक ही Tauri ऐप, पहले तीनों डेस्कटॉप (Linux / macOS / Windows; मोबाइल बाद में)
- [x] क्लाइंट यह कर सके: लॉगिन, संपर्क जोड़ना (DID से), एक-से-एक बातचीत, और उद्धरण देखना
- [x] WebSocket से वास्तविक समय में संदेश भेजना (एक इंस्टेंस काफ़ी है; NATS fan-out नहीं)
- [x] SSE से LLM का धारा-रूप आउटपुट
- [x] Docker Compose से एक ही आदेश में स्थानीय विकास-परिवेश

**Out of scope**:

- समूह-बातचीत, कई उपकरणों पर fan-out, मोबाइल, बहुभाषी UI, CDN, बाहरी OAuth, जटिल नीतियाँ
- Claude Code का प्लगिन अभी इसमें नहीं है

**Acceptance**:

दो डेवलपर अपने-अपने यहाँ एक-एक Confer इंस्टेंस चलाएँ, एक-दूसरे को जोड़ें, बात करें, और उद्धरण देख सकें।

## Claude Code के लिए कार्यान्वयन-संकेत

1. **पहले इकाई परीक्षण, फिर एकीकरण**: हर सेवा अपने परीक्षण अकेले चला सके, बाक़ी सेवाओं के उठने पर निर्भर न हो
2. **डेटाबेस का migration migration औज़ार से ही हो**, हाथ से SQL नहीं
3. **types `@confer/shared` पैकेज से साझा हों**, आगे और पीछे दोनों काम में लाएँ
4. **हर PR के साथ दस्तावेज़ का बदलाव हो** (यदि प्रोटोकॉल या API छुआ हो)
5. **A2A प्रोटोकॉल के लिए पहले से बनी लाइब्रेरी को वरीयता दें** (जैसे `http-message-signatures` npm पैकेज), पहिया दोबारा न गढ़ें
6. **DID:web के लिए `did-resolver` + `did-jwt`** जैसे W3C औज़ारों को वरीयता दें
7. **MCP सर्वर के लिए आधिकारिक SDK को वरीयता दें** (`@modelcontextprotocol/sdk`)
8. **commit का विषय ऐसा एक वाक्य लिखें जो बताए कि यह बदलाव क्या करता है**, conventional उपसर्ग नहीं। ध्यान रहे: `.github/scripts/gen-release-notes.sh` केवल `feat:` / `fix:` जैसे उपसर्ग पहचानता है, इसलिए रिलीज़ नोट हाथ से लिखने होंगे — गद्य विषयों से वह नहीं बनाएगा
