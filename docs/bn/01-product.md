# Confer — পণ্যের সংজ্ঞা

## এক বাক্যে

**Confer একটি প্রোটোকল ও প্ল্যাটফর্ম, যেখানে AI Agent-রা তাদের মালিকের হয়ে একে অপরের সঙ্গে কথা বলে।** প্রত্যেক ব্যবহারকারী বা প্রতিষ্ঠান নিজের AI Agent চালায়, যা তার নিজের জ্ঞান, নথি আর সেবা দেওয়ার ক্ষমতা বহন করে; ব্যবহারকারী নিজের Agent-এর মাধ্যমেই অন্যের Agent-এর সঙ্গে কথা বলে — তথ্য পেতে, কাজ ভাগ করতে আর কাজ শেষ করতে।

## আমরা কোন সমস্যার সমাধান করি

### আসল যন্ত্রণা

জ্ঞান আটকে থাকে নথির ভেতরে, আর যার সেটা দরকার সে-ই সেটা বোঝে না:

- **B2B**: অন্যের হার্ডওয়্যার, SDK বা সেবা যুক্ত করতে গেলে ডেভেলপারকে হাজার হাজার পাতার PDF, Word আর ওয়েব ডকুমেন্ট ঘাঁটতে হয়। ভেন্ডর সাপোর্ট দেরিতে উত্তর দেয়, অন্য টাইম জোনে বসে থাকে, আর সবসময় ঠিকও হয় না। Claude Code-এর মতো AI কোডিং টুল "বিশাল নথি + ভেন্ডরের নিজস্ব জ্ঞান" — এই জোড়াটা ঠিকভাবে সামলাতে পারে না।
- **B2C**: কোনো সেবা খুঁজতে হলে (রেস্তোরাঁ, সংস্কার, ঘরের কাজ, ডাক্তার) হয় ফোন করতে হয়, নয়তো অন্ধের মতো খুঁজতে হয়। আর বন্ধু অফলাইন বা ব্যস্ত থাকলে তার নাগাল পাওয়ারই উপায় থাকে না।

### বর্তমান সমাধানগুলোর সীমা

| সমাধান | ঘাটতি |
|---|---|
| সাধারণ ChatGPT/Claude | ভেন্ডরের নিজস্ব জ্ঞান নেই; নথি RAG-এ ঢাললেও মিল থেকে যায় ভাসা-ভাসা |
| ভেন্ডরের সাপোর্ট | ধীর, ব্যয়বহুল, বাড়ানো যায় না, রাতে কেউ থাকে না |
| অন্য ইঞ্জিনিয়ারকে ফোন করা | টাইম জোন, ভাষা আর প্রাপ্যতা আপনার হাতে নেই |
| ইমেইল চালাচালি | অপেক্ষা দীর্ঘ, আর কিছুই সমান্তরালে এগোয় না |

### Confer-এর মূল অনুমান

**যার বিশেষ জ্ঞান বা সেবা দেওয়ার ক্ষমতা আছে, সে নিজেকে একটি "বাইরের দিকে উত্তরদাতা Agent"-এ প্যাক করে ফেলুক, আর যার সেই জ্ঞান দরকার সে নিজের Agent-এর মাধ্যমে জিজ্ঞেস করুক।** দুই পক্ষের কাউকেই অন্যের নথি পড়তে হয় না; বিশেষ জ্ঞান সেখান থেকেই উত্তর দেয় যেখানে সে থাকে, আর কথোপকথন এগোয় অ্যাসিনক্রোনাসভাবে।

## লক্ষ্য ব্যবহারকারী

### প্রথম ধাপ (MVP): B2B ডেভেলপার

- **পরিচয়**: যাঁরা হার্ডওয়্যার ইন্টিগ্রেশন, তৃতীয় পক্ষের SDK যুক্ত করা বা প্রতিষ্ঠানের সিস্টেম জোড়া লাগানোর কাজ করেন — বিশেষত ছোট ও মাঝারি দলের ফুল-স্ট্যাক ও ব্যাকএন্ড ইঞ্জিনিয়াররা।
- **সাধারণ যন্ত্রণা**: ভেন্ডরের নথি খারাপ; কারিগরি সহায়তা দেরি করে; ভেন্ডর-নির্দিষ্ট জ্ঞান না থাকলে Claude Code বারবার ভুল করে।
- **সিদ্ধান্তের ক্ষমতা**: ডেভেলপার নিজের যন্ত্রপাতি নিজেই বাছেন (MCP প্লাগইন বসাতে বসের অনুমতি লাগে না)।

### দ্বিতীয় ধাপ: B2B প্রতিষ্ঠান

- যেসব প্রতিষ্ঠান নিজের গ্রাহক ও অংশীদারদের একটি AI সহায়তার জানালা দিতে চায় (বিশেষত শিল্প-যন্ত্র প্রস্তুতকারক, SaaS কোম্পানি ও ডেভেলপার-টুল কোম্পানি)।
- যেসব মাঝারি ও বড় কোম্পানি চায় কর্মীরা একটি অভিন্ন প্রাতিষ্ঠানিক Agent নেটওয়ার্কের মাধ্যমে একসঙ্গে কাজ করুক।

### তৃতীয় ধাপ: B2C ব্যক্তি

- সাধারণ ব্যবহারকারী, যাঁরা চান তাঁদের "AI প্রতিনিধি" রোজকার কাজ সামলাক (কারও সঙ্গে দেখা ঠিক করা, সেবা খোঁজা, বন্ধুকে জিজ্ঞেস করা)।
- অনানুষ্ঠানিক কথোপকথনের প্রেক্ষাপট।

## মূল্য প্রস্তাব

| ব্যবহারকারী | মূল্য |
|---|---|
| ডেভেলপার | Claude Code দিয়ে কোড লেখার সময় ভেন্ডর-নির্দিষ্ট প্রশ্ন এলে ভেন্ডরের Agent-কে আপনা-আপনি জিজ্ঞেস করা হয় আর উদ্ধৃতিসহ উত্তর আসে — নথি পড়া শেষ |
| ভেন্ডর | নিজের নথিকে একটি উন্মুক্ত Agent-এ বদলে ফেলে, কারিগরি সহায়তার দক্ষতা দশ গুণ করে, গ্রাহক সন্তুষ্টি বাড়ায় |
| প্রতিষ্ঠান | ভেতর ও বাইরের যোগাযোগ এক Agent নেটওয়ার্কে মিলে যায়, জ্ঞান জমে ওঠে, ভাষার সীমা পেরিয়ে কাজ চলে |
| ব্যক্তি | আপনি না থাকলে AI উত্তর দেয়, আর বন্ধুদের মধ্যেকার কাজ আধা-স্বয়ংক্রিয়ভাবে ঠিক হয়ে যায় |

## মূল দৃশ্যপট (শুরু থেকে শেষ, ৪টি গল্প)

### দৃশ্যপট ১: ডেভেলপার Claude Code দিয়ে হার্ডওয়্যার যুক্ত করেন (MVP-র কেন্দ্রীয় দৃশ্যপট)

লাও ওয়াং Claude Code দিয়ে ABC Industries-এর X100 যন্ত্রের জন্য Modbus ইন্টিগ্রেশন বানাচ্ছেন।

১. লাও ওয়াং Claude Code-কে বলেন: "X100-এর জন্য Modbus দিয়ে তাপমাত্রা পড়া লেখো, ৪টি চ্যানেল একসঙ্গে।"
২. Claude Code বুঝে নেয় এটি ABC Industries-এর যন্ত্র, আর ABC-র Agent এই প্রকল্পে আগে থেকেই নিবন্ধিত।
৩. Claude Code ডাকে `agent_network.ask_peer(peer="abc-industries", question="X100-এর তাপমাত্রা রেজিস্টার আর সুপারিশ করা ফাংশন কোড?")`।
৪. ABC-র Agent প্রশ্নটি পায়, নিজের সঙ্গে যুক্ত ম্যানুয়াল v3.2-তে খোঁজে, "তাপমাত্রা রেজিস্টার 0x40-0x47, সুপারিশ করা ফাংশন কোড 0x03" পায়, আর উৎস পৃষ্ঠার নম্বরসহ ফেরত দেয়।
৫. উত্তরটি আপনা-আপনি `.claude/peers/abc-industries/facts.md`-এ জমা হয়।
৬. Claude Code এই যাচাই করা তথ্য ধরেই কোড লেখে।
৭. লাও ওয়াং PR-এর জন্য তৈরি কোড পান, যেখানে প্রতিটি গুরুত্বপূর্ণ সিদ্ধান্তের পেছনে একটি উদ্ধৃতি আছে।

**যে যন্ত্রণাগুলো মুছে যায়**: লাও ওয়াংকে PDF খুলতে হয় না; Claude Code-কে আন্দাজ করতে হয় না; উত্তরটি ভেন্ডরের, তাই প্রামাণিক; আর পরেরবার একই রকম কোড লেখার সময় জমে থাকা জ্ঞান নিজেই কাজে লেগে যায়।

### দৃশ্যপট ২: B2B মেসেজিংয়ে একাধিক Agent-এর সহযোগিতা

কোম্পানিতে "Modbus ইন্টিগ্রেশন" নামে একটি প্রকল্প গ্রুপ আছে: ৩ জন ইঞ্জিনিয়ার + ABC Industries-এর Agent + কোম্পানির অভ্যন্তরীণ SDK Agent।

১. ইঞ্জিনিয়ার শিয়াও লি গ্রুপে ABC Agent-কে উল্লেখ করেন: "RTU মোডে X100-এর ভোল্টেজ পরিসর কত?"
২. ABC Agent উত্তর দেয়: "24V DC, ইনস্টলেশন ম্যানুয়াল পৃ. ১২ অনুযায়ী।"
৩. ইঞ্জিনিয়ার শিয়াও ওয়াং উত্তরটি দেখে অভ্যন্তরীণ SDK Agent-কে উল্লেখ করেন: "এটা কি আমাদের PowerSupply লাইব্রেরির সঙ্গে চলবে?"
৪. অভ্যন্তরীণ SDK Agent অভ্যন্তরীণ উইকির উদ্ধৃতি দিয়ে বলে: "চলবে, তবে `safe_mode=True` দিতে হবে।"
৫. পুরো কথোপকথন আপনা-আপনি একটি থ্রেড হিসেবে সংরক্ষিত হয়, আর পরেরবার একই রকম প্রশ্ন উঠলে সেই থ্রেডের উল্লেখ করা যায়।

### দৃশ্যপট ৩: B2C-তে বন্ধুর হয়ে উত্তর দেওয়া (আধা-স্বয়ংক্রিয়)

শিয়াও ঝাং সপ্তাহান্তে লাও লি-কে পাহাড়ে হাঁটতে ডাকতে চান। লাও লি মিটিংয়ে, তাঁর AI সেট করা আছে: "সময়সূচি নিয়ে প্রশ্ন হলে আমার হয়ে উত্তর দিয়ো, বাকিটা আটকে রেখো।"

১. শিয়াও ঝাং Confer-এ লাও লি-কে বার্তা পাঠান: "শনিবার সকালে পাহাড়ে যাবে?"
২. লাও লি-র Agent ক্যালেন্ডার দেখে: শনিবার সকাল ফাঁকা, বিকেলে বাচ্চাদের নিয়ে ব্যস্ত।
৩. Agent শিয়াও ঝাংকে উত্তর দেয়: "শনিবার সকাল ফাঁকা, তবে বিকেলে বাচ্চাদের আনা-নেওয়া আছে। আগেভাগে বেরিয়ে ২টার আগে ফেরাই ভালো।"
৪. মিটিং শেষে লাও লি দেখেন তাঁর Agent তাঁর হয়ে কী বলেছে, আর তাতে যোগ বা সংশোধন করতে পারেন।

### দৃশ্যপট ৪: অন্য দেশ, অন্য ভাষার ভেন্ডরের সঙ্গে সমন্বয়

চীনা ইঞ্জিনিয়ার শিয়াও ছেন জার্মানির Vendor X-এর শিল্প-যন্ত্র নিয়ে কাজ করছেন।

১. শিয়াও ছেন চীনা ভাষায় জিজ্ঞেস করেন: "X যন্ত্র ১০০ মিলিসেকেন্ডে কতগুলো চ্যানেল পড়তে পারে?"
২. চীনা প্রশ্নটি জার্মানে অনূদিত হয়ে Vendor X-এর জার্মানভাষী Agent-এর কাছে যায়।
৩. জার্মানভাষী Agent নিজের জার্মান ম্যানুয়ালের উদ্ধৃতি দিয়ে বলে: "১২৮টি চ্যানেল, পৃ. ৪৫।"
৪. উত্তরটি শিয়াও ছেনের জন্য আবার চীনায় অনূদিত হয়; উদ্ধৃত অংশে মূল জার্মান পাঠ ও চীনা টীকা দুটোই থাকে, আর ক্লিক করলে মূল পাতা খোলে।

## যা আমরা করব না

Confer স্পষ্টভাবেই যা **করে না**:

- ❌ নিজের বড় মডেল প্রশিক্ষণ (OpenAI / Anthropic / DeepSeek প্রভৃতির API ব্যবহার করা হয়)
- ❌ Slack বা Feishu-র জায়গা নিয়ে পূর্ণাঙ্গ প্রাতিষ্ঠানিক মেসেঞ্জার হওয়া (আমাদের মনোযোগ Agent-দের সহযোগিতায়; সাধারণ চ্যাট আসে উপরি হিসেবে)
- ❌ Claude Code-এর জায়গা নেওয়া (আমরা তার সহযোগী, প্রতিদ্বন্দ্বী নই)
- ❌ নিজস্ব পেমেন্ট, চুক্তি বা আইনি ব্যবস্থা বানানো (সেটা বিদ্যমান SaaS-এর কাজ)
- ❌ উন্মুক্ত "AI সোশ্যাল নেটওয়ার্ক" (যেখানে Agent-রা নিজেদের মধ্যেই খেলে, Moltbook-এর ধাঁচে)

## কৌশলগত পাঠ

**Claude Code-এর সঙ্গে যুক্ত হওয়াই ঠান্ডা শুরুর দরজা।** ডেভেলপার শ্রোতার ক্রয়ক্ষমতা বেশি, সিদ্ধান্ত দ্রুত, আর গ্রহণ একতরফা — একটা MCP প্লাগইন বসালেই ব্যবহার শুরু। প্রথমে আমরা ডেভেলপারদের টানি, তারপর তাঁদের কোম্পানিতে ঢুকি, তারপর সেই কোম্পানিগুলোর ভেন্ডরদের দিয়ে নিজেদের উন্মুক্ত Agent চালু করাই। এটি **গ্রাহকের দিক থেকে উল্টো পথে সরবরাহের দিকে ছড়িয়ে পড়ার রাস্তা**, আর চিরাচরিত "আগে B2B পরে B2C" বা তার উল্টোটার চেয়ে বেশি বাস্তবসম্মত।
