# Confer — MVP-র পথনকশা ও বাকি কাজ

milestone ধরে ভাগ করা; প্রতিটি milestone এমন একটি সংস্করণ যা হস্তান্তর ও প্রদর্শন করা যায়।

## v0.1 — Core proof of concept (৪-৬ সপ্তাহ)

**লক্ষ্য**: একটি যন্ত্রেই «ব্যবহারকারী ↔ নিজের Agent ↔ ওপাশের Agent» — গোটা শৃঙ্খলটি চলুক।

**পরিধি (অবশ্যকরণীয়)**

- [x] ব্যাকএন্ড: gateway + agent runtime + conversation + identity (চারটি সেবা; এক প্রসেসে হোক বা আলাদা, দুই-ই চলবে)
- [x] PostgreSQL-এর schema (দেখুন 04-data-model.md), migration সরঞ্জাম দিয়ে সামলানো
- [x] ব্যবহারকারীর নিবন্ধন / লগইন (কেবল পাসওয়ার্ডই যথেষ্ট; OAuth বা passkey নয়)
- [x] DID:web নথি তৈরি ও প্রকাশ (`/.well-known/did.json`)
- [x] AgentFacts নথি তৈরি ও প্রকাশ
- [ ] A2A প্রোটোকল — ভিতরে আসা ও বাইরে যাওয়া (HTTP স্বাক্ষরের যাচাই + capability token-এর যাচাই)
- [x] agent runtime: LLM ডাকার চক্র (আপাতত কেবল দুটি সরবরাহকারী — Claude আর DeepSeek)
- [x] সরল নীতি-ইঞ্জিন: শ্বেততালিকার peer, আর হয় সব অনুমোদিত নয় সব নাকচ
- [x] ক্লায়েন্ট: একটিই Tauri অ্যাপ, প্রথমে তিন ডেস্কটপ (Linux / macOS / Windows; মোবাইল পরে)
- [x] ক্লায়েন্ট যা পারবে: লগইন, পরিচিত যোগ করা (DID দিয়ে), এক-এক কথোপকথন, আর উদ্ধৃতি দেখা
- [x] WebSocket দিয়ে প্রকৃত সময়ে বার্তা পাঠানো (একটি ইনস্ট্যান্সই যথেষ্ট; NATS fan-out নয়)
- [x] SSE দিয়ে LLM-এর ধারা-আকারে আউটপুট
- [x] Docker Compose দিয়ে এক ধাপে স্থানীয় উন্নয়ন-পরিবেশ

**Out of scope**:

- দলগত কথোপকথন, একাধিক যন্ত্রে fan-out, মোবাইল, বহুভাষিক UI, CDN, বাইরের OAuth, জটিল নীতি
- Claude Code-এর প্লাগিন এখনও এর মধ্যে নেই

**Acceptance**:

দুজন ডেভেলপার নিজ নিজ জায়গায় একটি করে Confer ইনস্ট্যান্স চালান, একে অপরকে যোগ করেন, কথা বলেন, আর উদ্ধৃতি দেখতে পান।

## v0.2 — Claude Code প্লাগিনের MVP (৩-৪ সপ্তাহ)

**লক্ষ্য**: Claude Code-এর ভিতর থেকেই peer Agent-এর পরামর্শ নেওয়া যাক, আর উত্তর প্রকল্পে জমা হোক।

**Scope**:

- [x] MCP সার্ভার বানানো — বাস্তবে আছে পনেরোটি যন্ত্র (`ask_agent`, `list_agents`, `read_project_memory`, `write_project_memory`, `request_code_review` প্রভৃতি); এই লাইনে আগে লেখা `ask_peer` / `list_peers` কখনোই সত্যিকারের যন্ত্র-নাম ছিল না
- [ ] OAuth-ধাঁচে Confer অ্যাকাউন্টকে Claude Code ইনস্ট্যান্সের সঙ্গে জোড়া
- [ ] `.claude/confer.toml` বিন্যাস ফাইলের বিশ্লেষণ
- [ ] `.claude/peers/{slug}/` ডিরেক্টরির পড়া-লেখা (facts.md, decisions.md, conversations/, meta.json)
- [ ] তথ্যের স্বয়ংক্রিয় নিষ্কাশন: ask_peer-এর পর উত্তর থেকে কাঠামোবদ্ধ তথ্য বার করে facts.md-এ লেখা
- [ ] `confer` কমান্ড-লাইন সরঞ্জাম (add peer, list peers, ask, sync)
- [ ] একটি ডেমো peer Agent (mock-vendor.confer.dev), যাতে ডেভেলপাররা পরখ করতে পারেন

**Acceptance**:

কেউ `claude mcp add confer` বসিয়ে, বিন্যাস করে, Claude Code-এ mock vendor-কে প্রশ্ন করতে পারেন; উত্তর উদ্ধৃতিসহ আসে, `.claude/peers/mock-vendor/facts.md`-এ লেখা হয়, git-এ commit হয়, আর পরের session-এ আপনা থেকেই লোড হয়।

## v0.3 — দলগত কথোপকথন ও প্রাতিষ্ঠানিক ইনস্ট্যান্স (৪-৫ সপ্তাহ)

**লক্ষ্য**: দলগত কথোপকথন (মানুষ ও Agent মিলিয়ে) সামলানো, আর একটি যন্ত্রে «প্রাতিষ্ঠানিক ইনস্ট্যান্স» মোতায়েন করতে পারা।

**Scope**:

- [ ] দলের ডেটা মডেল ও UI
- [ ] দলের সদস্য ব্যবস্থাপনা (মানুষ ও Agent যোগ করা / সরানো)
- [ ] একাধিক @ করা Agent একসঙ্গে উত্তর দিক (গুটিয়ে দেখানো, «গ্রহণ» করার ব্যবস্থা)
- [ ] প্রাতিষ্ঠানিক ইনস্ট্যান্স: নিজস্ব ডোমেইন আর SSO লগইন (OIDC হলেই চলবে)
- [x] পরিচিত খোঁজা: ডোমেইন ধরে (acme.com লিখলেই ওই ডোমেইনের প্রকাশ্য Agent মিলুক)
- [ ] একাধিক যন্ত্রে fan-out (গেটওয়ে এখন একক-ইনস্ট্যান্স: WS সংযোগ-তালিকা, A2A replay nonce ও হার-সীমার গণনা সবই প্রক্রিয়ার ভিতরের `Map`। যে Redis/NATS বিন্যাসে কখনো সংযোগ করা হয়নি তা 2026-08-07-এ মুছে ফেলা হয়েছে; কাজটি ধরার সময় আগে এই তিনটি সরাতে হবে, সবার আগে nonce)
- [ ] মোবাইল (iOS, Android)

**Acceptance**:

পাঁচজনের ছোট দল আর ২টি Agent একটি দলে প্রকল্প নিয়ে আলোচনা চালান, আর অভিজ্ঞতা মসৃণ থাকে। কোনো কোম্পানি নিজের Confer ইনস্ট্যান্স গড়তে পারে, বাইরের জন্য প্রকাশ্য Agent দেখাতে পারে, আর অন্য ইনস্ট্যান্স তাকে খুঁজে পায়।

## v0.4 — বহুভাষিকতা ও অনুপস্থিতিতে উত্তর (৩ সপ্তাহ)

**লক্ষ্য**: পণ্যটিকে আন্তর্জাতিক প্রেক্ষিতে আর আধা-অ্যাসিনক্রোনাস যোগাযোগে কাজে লাগানোর মতো করা।

**Scope**:

- [x] UI-র i18n (চীনা ও ইংরেজি দিয়ে শুরু, জাপানি/জার্মান/ফরাসির জন্য জায়গা রেখে)
- [ ] Agent-দের মধ্যে ভাষা-পার কথোপকথন (অনুবাদ হয় লক্ষ্য Agent-এর ভিতরে, উদ্ধৃতিতে মূল পাঠ থেকে যায়)
- [ ] AgentFacts-এ `primary_language` ক্ষেত্র যোগ
- [ ] অনুপস্থিতিতে উত্তর: standing policy ঠিক করার UI + ঝুলন্ত ইনবক্স + push বিজ্ঞপ্তি
- [x] MCP সার্ভারে pre-flight design review যন্ত্র যোগ
- [x] MCP সার্ভারে post-flight code review যন্ত্র যোগ

**Acceptance**:

চীনের ডেভেলপার চীনা ভাষায় জার্মান সরবরাহকারীর Agent-কে জিজ্ঞেস করেন (যার নথি জার্মানে), আর চীনায় উত্তর + জার্মান মূলের উদ্ধৃতি পান। standing policy ঠিক করা থাকলে, মালিক অনুপস্থিত থাকলেও Agent নিয়মে মেলা অনুরোধ ঠিকঠাক সামলায়, আর সন্দেহজনকগুলো ঝুলিয়ে রাখে।

1. স্পষ্ট ইনপুট-আউটপুট থাকুক

## Claude Code-এর জন্য বাস্তবায়নের ইঙ্গিত

1. **আগে একক পরীক্ষা, পরে একীভবন**: প্রতিটি সেবা নিজের পরীক্ষা একাই চালাতে পারুক, অন্য সেবা ওঠার উপর নির্ভর না করুক
2. **ডেটাবেসের migration migration সরঞ্জাম দিয়েই হোক**, হাতে SQL নয়
3. **types `@confer/shared` প্যাকেজ দিয়ে ভাগ হোক**, সামনে-পিছনে দুই দিকেই কাজে লাগুক
4. **প্রতিটি PR-এর সঙ্গে নথির বদল থাকুক** (যদি প্রোটোকল বা API ছোঁয়া হয়)
5. **A2A প্রোটোকলের জন্য আগে থেকে থাকা লাইব্রেরিকে অগ্রাধিকার দিন** (যেমন `http-message-signatures` npm প্যাকেজ), চাকা নতুন করে বানাবেন না
6. **DID:web-এর জন্য `did-resolver` + `did-jwt`** — এই W3C সরঞ্জামগুলোকে অগ্রাধিকার দিন
7. **MCP সার্ভারের জন্য দাপ্তরিক SDK-কে অগ্রাধিকার দিন** (`@modelcontextprotocol/sdk`)
8. **commit-এর বিষয় এমন একটি বাক্যে লিখুন যা বলে এই বদল কী করে**, conventional উপসর্গ নয়। খেয়াল রাখুন: `.github/scripts/gen-release-notes.sh` কেবল `feat:` / `fix:` ধাঁচের উপসর্গ চেনে, তাই মুক্তি-নোট হাতে লিখতে হবে — গদ্য বিষয় থেকে সে বানাবে না
