# Confer — خارطة طريق النسخة الأولى وما بقي من عمل

مقسَّمة إلى محطات؛ وكل محطة نسخة قابلة للتسليم والعرض.

## v0.1 — Core proof of concept (4-6 أسابيع)

**الهدف**: أن تعمل على جهاز واحد سلسلةُ «المستخدم ← وكيله ← وكيل الطرف الآخر» من طرفها إلى طرفها.

**النطاق (الواجب)**

- [x] الخادوم: gateway وagent runtime وconversation وidentity (أربع خدمات، في عملية واحدة أو منفصلة، لا فرق)
- [x] مخطّط PostgreSQL (انظر 04-data-model.md)، مُدارًا بأداة ترحيل
- [x] تسجيل المستخدمين ودخولهم (كلمة المرور تكفي؛ لا OAuth ولا passkey)
- [x] توليد مستند DID:web ونشره (`/.well-known/did.json`)
- [x] توليد مستند AgentFacts ونشره
- [ ] بروتوكول A2A واردًا وصادرًا (التحقّق من توقيع HTTP + التحقّق من capability token)
- [x] agent runtime: حلقة استدعاء النموذج (مزوّدان فقط في البداية: Claude وDeepSeek)
- [x] محرّك سياسات بسيط: أقران في قائمة بيضاء، وإما السماح بكل شيء أو المنع من كل شيء
- [x] العميل: تطبيق Tauri واحد، ولأنظمة سطح المكتب الثلاثة أولًا (Linux وmacOS وWindows؛ والهاتف لاحقًا)
- [x] أن يقدر العميل على: الدخول، وإضافة جهات اتصال (بالـDID)، والمحادثة الثنائية، ورؤية الاستشهادات
- [x] دفع الرسائل آنيًا عبر WebSocket (نسخة واحدة تكفي؛ من دون توزيع NATS)
- [x] إخراج النموذج تدفّقًا عبر SSE
- [x] بيئة تطوير محلية بأمر واحد عبر Docker Compose

**Out of scope**:

- المحادثات الجماعية، والتوزيع على عدة أجهزة، والهاتف، والواجهة متعدّدة اللغات، وشبكة توصيل المحتوى، وOAuth الخارجي، والسياسات المعقّدة
- إضافة Claude Code ليست ضمن هذه الدفعة بعد

**Acceptance**:

يشغّل مطوّران عند كل منهما نسخةً محلية من Confer، فيضيف كلٌّ الآخر، ويتحادثان، ويريان الاستشهادات.

## المخاطر والقرارات المبكّرة اللازمة

| الخطر | التخفيف |
|---|---|
| ما زال SDK الخاص بـMCP يتطوّر، وقد تنكسر واجهته | التزام النسخة المستقرّة، ومتابعة changelog، وبناء طبقة تكيّف |
| بروتوكول A2A (من Google) ومعيار NANDA ما زالا يتطوّران أيضًا | البدء بأصغر مجموعة جزئية، مع ترك مكان لطبقة تكيّف البروتوكول |
| Tauri 2.0 على iOS وAndroid حديث نسبيًا، وقد تعترضك عقبات | في طور النسخة الأولى: أنظمة سطح المكتب الثلاثة فقط، والهاتف في v0.3 |
| خروج كلفة النماذج عن السيطرة | حصّة افتراضية + BYO key صريح + لوحة استهلاك مبكرة |
| حزم تطوير مزوّدي النماذج الصينيين (DeepSeek/Qwen) غير مستقرّة | اتّخاذ الواجهة المتوافقة مع OpenAI (وكلّهم يدعمونها) نقطةَ دخول موحّدة |

## إرشادات التنفيذ لأجل Claude Code

1. **الاختبارات الوحدوية قبل التكامل**: يجب أن تجتاز كل خدمة اختباراتها وحدها، من غير أن تتوقّف على إقلاع غيرها
2. **ترحيل قاعدة البيانات يمرّ بأداة الترحيل**، لا بـSQL مكتوب باليد
3. **تُشارَك الأنواع عبر حزمة `@confer/shared`**، ينتفع بها الطرفان
4. **كل طلب دمج يحمل تعديل توثيقه** (إن مسّ البروتوكول أو الواجهة)
5. **يُفضَّل في تنفيذ بروتوكول A2A مكتبةٌ جاهزة** (كحزمة npm المسمّاة `http-message-signatures`) على إعادة اختراع العجلة
6. **ويُفضَّل لـDID:web استعمال `did-resolver` و`did-jwt`**، وهي من أدوات W3C
7. **ويُفضَّل لخادوم MCP استعمال SDK الرسمي** (`@modelcontextprotocol/sdk`)
8. **اكتب عنوان الإيداع جملةً تقول ما يفعله التغيير**، لا بادئةً اصطلاحية. وانتبه: `.github/scripts/gen-release-notes.sh` لا يعرف إلا البادئات من نوع `feat:` و`fix:`، فملاحظات الإصدار تُكتب باليد — ولن يولّدها من عناوين نثرية
