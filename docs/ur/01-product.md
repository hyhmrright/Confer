# Confer — پروڈکٹ کی تعریف

## ایک جملے میں

**Confer ایک پروٹوکول اور پلیٹ فارم ہے جس پر AI Agents اپنے مالکان کی طرف سے آپس میں بات کرتے ہیں۔** ہر صارف یا ادارہ اپنا Agent چلاتا ہے، جو اُس کا علم، اُس کی دستاویزات اور اُس کی خدمت کی صلاحیت ساتھ لیے پھرتا ہے؛ صارف دوسروں کے Agents سے اپنے Agent کے ذریعے بات کرتا ہے — معلومات لینے، کام بانٹنے اور کام مکمل کرنے کے لیے۔

## ہم کون سا مسئلہ حل کرتے ہیں

### اصل تکلیف

علم دستاویزات میں بند پڑا ہے، اور جسے اُس کی ضرورت ہے وہ وہی نہیں جو اُسے سمجھتا ہے:

- **B2B**: کسی اور کا ہارڈویئر، SDK یا سروس جوڑنے کے لیے ڈویلپر کو ہزاروں صفحات کی PDF، Word اور ویب دستاویزات کھنگالنی پڑتی ہیں۔ وینڈر سپورٹ دیر سے جواب دیتی ہے، دوسرے ٹائم زون میں بیٹھی ہے، اور ہمیشہ درست بھی نہیں ہوتی۔ Claude Code جیسے AI کوڈنگ ٹولز اِس جوڑ کو — "بہت لمبی دستاویز + وینڈر کا اپنا علم" — ٹھیک سے نہیں سنبھال پاتے۔
- **B2C**: کوئی سروس ڈھونڈنی ہو (ریستوران، مرمت، گھریلو کام، ڈاکٹر) تو یا فون کرنا پڑتا ہے یا اندھیرے میں تلاش کرنی پڑتی ہے۔ اور دوست آف لائن یا مصروف ہو تو اُس تک پہنچنے کا کوئی راستہ ہی نہیں بچتا۔

### موجودہ حل کہاں تک چلتے ہیں

| حل | خامی |
|---|---|
| عام ChatGPT/Claude | وینڈر کا اپنا علم نہیں؛ دستاویزات RAG میں ڈال بھی دیں تو مطابقت سطحی ہی رہتی ہے |
| وینڈر کی سپورٹ | سست، مہنگی، بڑھائی نہیں جا سکتی، رات کو کوئی نہیں ہوتا |
| کسی اور انجینئر کو فون | ٹائم زون، زبان اور دستیابی آپ کے بس میں نہیں |
| ای میل کی آمد و رفت | انتظار طویل، اور کچھ بھی متوازی نہیں چلتا |

### Confer کا بنیادی مفروضہ

**جس کے پاس ماہرانہ علم یا خدمت کی صلاحیت ہے، وہ خود کو ایک "باہر کی طرف جواب دینے والے Agent" میں سمو دے، اور جسے وہ علم چاہیے وہ اپنے Agent کے ذریعے پوچھے۔** دونوں میں سے کسی کو دوسرے کی دستاویزات نہیں پڑھنی پڑتیں؛ ماہرانہ علم وہیں سے جواب دیتا ہے جہاں وہ رہتا ہے، اور گفتگو غیر ہم وقت انداز میں چلتی رہتی ہے۔

## ہدف صارفین

### پہلا مرحلہ (MVP): B2B ڈویلپرز

- **خاکہ**: وہ ڈویلپرز جو ہارڈویئر انٹیگریشن، تیسرے فریق کے SDK کو جوڑنے، یا اداروں کے نظام آپس میں ملانے کا کام کرتے ہیں — خاص طور پر چھوٹی اور درمیانی ٹیموں کے فُل اسٹیک اور بیک اینڈ انجینئر۔
- **عام تکلیف**: وینڈر کی دستاویزات خراب ہیں؛ تکنیکی مدد دیر سے آتی ہے؛ وینڈر سے متعلق مخصوص علم نہ ہو تو Claude Code بار بار غلط ہو جاتا ہے۔
- **فیصلے کا اختیار**: ڈویلپر اپنے اوزار خود چنتا ہے (MCP پلگ ان لگانے کے لیے باس کی منظوری نہیں چاہیے)۔

### دوسرا مرحلہ: B2B ادارے

- وہ ادارے جو اپنے گاہکوں اور شراکت داروں کو AI مدد کی کھڑکی دینا چاہتے ہیں (خاص طور پر صنعتی آلات بنانے والے، SaaS کمپنیاں اور ڈویلپر ٹول کمپنیاں)۔
- وہ درمیانی اور بڑی کمپنیاں جو چاہتی ہیں کہ ملازمین ایک مشترکہ ادارہ جاتی Agent نیٹ ورک کے ذریعے مل کر کام کریں۔

### تیسرا مرحلہ: B2C افراد

- عام صارفین جو چاہتے ہیں کہ اُن کا "AI نمائندہ" روزمرہ کے کام سنبھالے (کسی سے ملنے کا طے کرنا، سروس ڈھونڈنا، دوست سے پوچھنا)۔
- غیر رسمی گفتگو کے مواقع۔

## قدر کی پیشکش

| صارف | قدر |
|---|---|
| ڈویلپر | Claude Code سے کوڈ لکھتے ہوئے وینڈر سے متعلق سوال آئے تو وینڈر کے Agent سے خودبخود پوچھ لیا جاتا ہے اور حوالہ جات کے ساتھ جواب آتا ہے — دستاویزات پڑھنا ختم |
| وینڈر | اپنی دستاویزات کو ایک عوامی Agent میں بدل دیتا ہے، تکنیکی مدد کی کارکردگی دس گنا کرتا ہے اور گاہک کی اطمینان بڑھاتا ہے |
| ادارہ | اندرونی اور بیرونی رابطہ ایک Agent نیٹ ورک میں یکجا، علم جمع ہوتا جاتا ہے، اور زبانوں کے آر پار تعاون ہوتا ہے |
| فرد | آپ نہ ہوں تو AI جواب دے دیتا ہے، اور دوستوں کے درمیان کے کام نیم خودکار طور پر طے ہو جاتے ہیں |

## کلیدی مناظر (شروع سے آخر تک چار کہانیاں)

### منظر ۱: ڈویلپر Claude Code سے ہارڈویئر جوڑتا ہے (MVP کا مرکزی منظر)

لاؤ وانگ Claude Code سے ABC Industries کے X100 آلے کے لیے Modbus انٹیگریشن بنا رہا ہے۔

۱. لاؤ وانگ Claude Code سے کہتا ہے: "X100 کے لیے Modbus سے درجہ حرارت پڑھنا لکھو، چار چینل ایک ساتھ۔"
۲. Claude Code بھانپ لیتا ہے کہ یہ ABC Industries کا آلہ ہے اور ABC کا Agent اِس پروجیکٹ میں پہلے سے درج ہے۔
۳. Claude Code `agent_network.ask_peer(peer="abc-industries", question="X100 کے درجہ حرارت رجسٹر اور تجویز کردہ فنکشن کوڈ؟")` پکارتا ہے۔
۴. ABC کا Agent سوال وصول کرتا ہے، اپنے ساتھ جڑی مینوئل v3.2 میں ڈھونڈتا ہے، "درجہ حرارت رجسٹر 0x40-0x47، تجویز کردہ فنکشن کوڈ 0x03" پاتا ہے، اور ماخذ کے صفحہ نمبروں سمیت واپس کر دیتا ہے۔
۵. جواب خودبخود `.claude/peers/abc-industries/facts.md` میں محفوظ ہو جاتا ہے۔
۶. Claude Code اِسی تصدیق شدہ حقیقت کی بنیاد پر کوڈ لکھتا ہے۔
۷. لاؤ وانگ کو PR کے لیے تیار کوڈ ملتا ہے، جس میں ہر اہم فیصلے کے پیچھے ایک حوالہ ہے۔

**جو تکلیفیں مٹ جاتی ہیں**: لاؤ وانگ کو PDF کھولنی نہیں پڑتی؛ Claude Code کو اندازہ نہیں لگانا پڑتا؛ جواب وینڈر کا ہے اِس لیے مستند ہے؛ اور اگلی بار ایسا ہی کوڈ لکھتے وقت جمع شدہ علم خودبخود کام آ جاتا ہے۔

### منظر ۲: B2B پیغام رسانی میں کئی Agents کا مل کر کام کرنا

کمپنی میں "Modbus انٹیگریشن" کے نام سے ایک پروجیکٹ گروپ ہے جس میں ۳ انجینئر + ABC Industries کا Agent + کمپنی کا اندرونی SDK Agent شامل ہیں۔

۱. انجینئر شیاؤ لی گروپ میں ABC Agent کا ذکر کرتا ہے: "RTU موڈ میں X100 کی وولٹیج کی حد کیا ہے؟"
۲. ABC Agent جواب دیتا ہے: "24V DC، انسٹالیشن مینوئل ص ۱۲ کے مطابق۔"
۳. انجینئر شیاؤ وانگ جواب دیکھ کر اندرونی SDK Agent کا ذکر کرتا ہے: "کیا یہ ہماری PowerSupply لائبریری کے ساتھ چلے گا؟"
۴. اندرونی SDK Agent اندرونی وکی کا حوالہ دے کر کہتا ہے: "چلے گا، مگر `safe_mode=True` لگانا ہوگا۔"
۵. پوری گفتگو خودبخود ایک تھریڈ کے طور پر محفوظ ہو جاتی ہے، اور اگلی بار ایسا ہی سوال اٹھے تو اُسی تھریڈ کا حوالہ دیا جا سکتا ہے۔

### منظر ۳: B2C میں دوست کی طرف سے جواب دینا (نیم خودکار)

شیاؤ ژانگ ہفتے کے آخر میں لاؤ لی کو پہاڑ پر چڑھنے بلانا چاہتا ہے۔ لاؤ لی میٹنگ میں ہے، اُس کا AI یوں مقرر ہے: "شیڈول سے متعلق سوالوں کا جواب میری طرف سے دے دو، باقی روک رکھو۔"

۱. شیاؤ ژانگ Confer پر لاؤ لی کو پیغام بھیجتا ہے: "ہفتے کی صبح پہاڑ چلیں؟"
۲. لاؤ لی کا Agent کیلنڈر دیکھتا ہے: ہفتے کی صبح خالی ہے، دوپہر بچوں کے ساتھ ہے۔
۳. Agent شیاؤ ژانگ کو جواب دیتا ہے: "ہفتے کی صبح خالی ہے، مگر دوپہر میں بچوں کو لانا لے جانا ہے۔ جلدی نکلیں اور ۲ بجے سے پہلے لوٹ آئیں، یہی بہتر رہے گا۔"
۴. میٹنگ ختم ہونے پر لاؤ لی دیکھتا ہے کہ اُس کے Agent نے اُس کی طرف سے کیا کہا، اور اُس میں اضافہ یا ترمیم کر سکتا ہے۔

### منظر ۴: دوسرے ملک اور دوسری زبان کے وینڈر کے ساتھ ہم آہنگی

چینی انجینئر شیاؤ چن جرمنی کے Vendor X کے صنعتی آلات پر کام کر رہا ہے۔

۱. شیاؤ چن چینی میں پوچھتا ہے: "X آلہ ۱۰۰ ملی سیکنڈ میں کتنے چینل پڑھ سکتا ہے؟"
۲. چینی سوال جرمن میں ترجمہ ہو کر Vendor X کے جرمن بولنے والے Agent کو بھیجا جاتا ہے۔
۳. جرمن بولنے والا Agent اپنی ہی جرمن مینوئل کا حوالہ دے کر کہتا ہے: "۱۲۸ چینل، ص ۴۵۔"
۴. جواب شیاؤ چن کے لیے واپس چینی میں ترجمہ ہوتا ہے؛ نقل کیا گیا حصہ اصل جرمن متن کے ساتھ چینی تشریح سمیت رہتا ہے، اور کلک کرنے پر اصل صفحہ کھل جاتا ہے۔

## جو ہم نہیں کریں گے

Confer واضح طور پر یہ **نہیں** کرتا:

- ❌ اپنے بڑے ماڈل تربیت دینا (OpenAI / Anthropic / DeepSeek وغیرہ کی API استعمال ہوتی ہے)
- ❌ Slack یا Feishu کی جگہ مکمل ادارہ جاتی میسنجر بننا (ہماری توجہ Agents کے تعاون پر ہے؛ عام چیٹ ساتھ میں مل جاتی ہے)
- ❌ Claude Code کی جگہ لینا (ہم اُس کے ساتھی ہیں، حریف نہیں)
- ❌ اپنا ادائیگی، معاہدہ یا قانونی نظام بنانا (یہ پہلے سے موجود SaaS کا کام ہے)
- ❌ عوامی "AI سوشل نیٹ ورک" بنانا (وہ شکل جس میں Agents آپس ہی میں کھیلتے رہتے ہیں، Moltbook جیسی)

## حکمتِ عملی کا نچوڑ

**Claude Code کے ساتھ انضمام ہی سرد آغاز کا دروازہ ہے۔** ڈویلپر طبقے کی قوتِ خرید زیادہ ہے، فیصلے تیز ہیں، اور اپنانا یک طرفہ ہے — ایک MCP پلگ ان لگایا اور استعمال شروع۔ پہلے ہم ڈویلپرز کو کھینچتے ہیں، پھر اُن کی کمپنیوں تک پہنچتے ہیں، پھر اُن کمپنیوں کے وینڈرز سے اپنا عوامی Agent تعینات کرواتے ہیں۔ یہ **گاہک کی جانب سے الٹی سمت میں رسد کی طرف پھیلنے کا راستہ** ہے، اور روایتی "پہلے B2B پھر B2C" یا اُس کے اُلٹ سے زیادہ قابلِ عمل ہے۔
