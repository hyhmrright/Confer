# Confer — MVP کا خاکہ اور باقی کام

milestone کے حساب سے ٹکڑے؛ ہر milestone ایک ایسا نسخہ ہے جو سونپا اور دکھایا جا سکے۔

## v0.1 — Core proof of concept (4-6 ہفتے)

**ہدف**: ایک ہی مشین پر «صارف ← اپنا Agent ← سامنے والا Agent» کی پوری زنجیر چل جائے۔

**دائرہ (لازمی)**

- [x] بیک اینڈ: gateway + agent runtime + conversation + identity (چار خدمات؛ ایک ہی پروسیس میں ہوں یا الگ الگ، دونوں چلے گا)
- [x] PostgreSQL کا schema (دیکھیں 04-data-model.md)، migration اوزار سے سنبھالا ہوا
- [x] صارف کا اندراج / لاگ اِن (صرف پاس ورڈ کافی ہے؛ OAuth یا passkey نہیں)
- [x] DID:web دستاویز بنانا اور پیش کرنا (`/.well-known/did.json`)
- [x] AgentFacts دستاویز بنانا اور پیش کرنا
- [ ] A2A پروٹوکول — اندر آنا اور باہر جانا (HTTP دستخط کی جانچ + capability token کی جانچ)
- [x] agent runtime: LLM بلانے کا چکر (فی الحال صرف دو فراہم کنندہ — Claude اور DeepSeek)
- [x] سادہ پالیسی انجن: سفید فہرست کے peer، اور یا سب اجازت یا سب انکار
- [x] کلائنٹ: ایک ہی Tauri ایپ، پہلے تینوں ڈیسک ٹاپ (Linux / macOS / Windows؛ موبائل بعد میں)
- [x] کلائنٹ یہ کر سکے: لاگ اِن، رابطہ شامل کرنا (DID سے)، ایک سے ایک گفتگو، اور حوالے دیکھنا
- [x] WebSocket سے حقیقی وقت میں پیغام بھیجنا (ایک انسٹنس کافی ہے؛ NATS fan-out نہیں)
- [x] SSE سے LLM کا رواں آؤٹ پٹ
- [x] Docker Compose سے ایک ہی حکم میں مقامی ترقیاتی ماحول

**Out of scope**:

- گروہی گفتگو، کئی آلات پر fan-out، موبائل، کثیر لسانی UI، CDN، بیرونی OAuth، پیچیدہ پالیسیاں
- Claude Code کا پلگ اِن ابھی اس میں نہیں

**Acceptance**:

دو ڈویلپر اپنے اپنے ہاں ایک ایک Confer انسٹنس چلائیں، ایک دوسرے کو شامل کریں، بات کریں، اور حوالے دیکھ سکیں۔

**ہدف**: Claude Code کے اندر ہی سے peer Agent سے مشورہ لیا جا سکے، اور جواب منصوبے میں جمع ہو۔

**Scope**:

- [x] MCP سرور بنانا — آج حقیقت میں پندرہ اوزار موجود ہیں (`ask_agent`، `list_agents`، `read_project_memory`، `write_project_memory`، `request_code_review` وغیرہ)؛ اس سطر میں پہلے لکھے `ask_peer` / `list_peers` کبھی حقیقی اوزار کے نام تھے ہی نہیں
- [ ] OAuth طرز پر Confer کھاتے کو Claude Code انسٹنس سے جوڑنا
- [ ] `.claude/confer.toml` ترتیب فائل کا تجزیہ
- [ ] `.claude/peers/{slug}/` ڈائریکٹری کا پڑھنا لکھنا (facts.md، decisions.md، conversations/، meta.json)
- [ ] حقائق کا خودکار استخراج: ask_peer کے بعد جواب سے ساختہ حقائق نکال کر facts.md میں لکھنا
- [ ] `confer` کمانڈ لائن اوزار (add peer، list peers، ask، sync)
- [ ] ایک ڈیمو peer Agent (mock-vendor.confer.dev)، جس پر ڈویلپر آزما سکیں

**Acceptance**:

کوئی `claude mcp add confer` لگائے، ترتیب دے، اور Claude Code میں mock vendor سے سوال کر سکے؛ جواب حوالوں سمیت آئے، `.claude/peers/mock-vendor/facts.md` میں لکھا جائے، git میں commit ہو، اور اگلے session میں خود بخود لد جائے۔

## v0.3 — گروہی گفتگو اور ادارہ جاتی انسٹنس (4-5 ہفتے)

**ہدف**: گروہی گفتگو (لوگ اور Agent ملے جلے) سنبھالنا، اور ایک مشین پر «ادارہ جاتی انسٹنس» تعینات کر سکنا۔

**Scope**:

- [ ] گروہ کا ڈیٹا ماڈل اور UI
- [ ] گروہ کے ارکان کا انتظام (لوگوں اور Agent کو شامل کرنا / نکالنا)
- [ ] کئی @ کیے گئے Agent بیک وقت جواب دیں (لپیٹ کر دکھانا، «قبول کرنے» کا طریقہ)
- [ ] ادارہ جاتی انسٹنس: اپنا ڈومین اور SSO لاگ اِن (OIDC ہی کافی)
- [x] رابطوں کی دریافت: ڈومین سے تلاش (acme.com لکھتے ہی اُس ڈومین کے عوامی Agent مل جائیں)
- [ ] کئی آلات پر fan-out (گیٹ وے اس وقت واحد instance ہے: WS رابطوں کی فہرست، A2A replay nonce اور شرح کی حد کے شمار سب عمل کے اندر `Map` ہیں۔ جس Redis/NATS ترتیب سے کبھی رابطہ ہی نہیں ہوا وہ 2026-08-07 کو ہٹا دی گئی؛ کام شروع کرتے وقت پہلے یہ تین منتقل کرنے ہوں گے، سب سے پہلے nonce)
- [ ] موبائل (iOS، Android)

**Acceptance**:

پانچ افراد کی ٹیم اور 2 Agent ایک ہی گروہ میں منصوبے پر بات کریں، اور تجربہ رواں رہے۔ کوئی کمپنی اپنا Confer انسٹنس کھڑا کر سکے، باہر کے لیے عوامی Agent پیش کرے، اور دوسرے انسٹنس اسے ڈھونڈ سکیں۔

## خطرات اور ابتدائی ضروری فیصلے

| خطرہ | تدارک |
|---|---|

| A2A پروٹوکول (Google) اور NANDA معیار — دونوں اب بھی ارتقا میں ہیں | سادہ ترین ذیلی مجموعے سے شروع کریں، پروٹوکول موافقت کی تہہ کے لیے جگہ رکھیں |

| LLM کی لاگت بے قابو ہو جائے | طے شدہ کوٹا + واضح BYO key + استعمال کا پینل جلد بنائیں |
| چینی LLM فراہم کنندگان (DeepSeek/Qwen) کے SDK مستحکم نہیں | OpenAI ہم آہنگ انٹرفیس کو (جو یہ سب فراہم کنندہ دیتے ہیں) واحد داخلی نقطہ بنائیں |

## Claude Code کے لیے نفاذ کے اشارے

1. **پہلے اکائی جانچ، پھر انضمام**: ہر خدمت اپنی جانچ اکیلے چلا سکے، باقی خدمات کے اٹھنے پر منحصر نہ ہو
2. **ڈیٹابیس کی migration، migration اوزار ہی سے ہو**، ہاتھ سے SQL نہیں
3. **types `@confer/shared` پیکج سے مشترک ہوں**، آگے پیچھے دونوں کام میں لائیں
4. **ہر PR کے ساتھ دستاویز کی تبدیلی ہو** (اگر پروٹوکول یا API چھوا ہو)
5. **A2A پروٹوکول کے لیے پہلے سے موجود لائبریری کو ترجیح دیں** (جیسے `http-message-signatures` npm پیکج)، پہیہ دوبارہ نہ گھڑیں
6. **DID:web کے لیے `did-resolver` + `did-jwt`** جیسے W3C اوزاروں کو ترجیح دیں
7. **MCP سرور کے لیے سرکاری SDK کو ترجیح دیں** (`@modelcontextprotocol/sdk`)
8. **commit کا عنوان ایسے ایک جملے میں لکھیں جو بتائے کہ یہ تبدیلی کیا کرتی ہے**، conventional سابقہ نہیں۔ خیال رہے: `.github/scripts/gen-release-notes.sh` صرف `feat:` / `fix:` جیسے سابقے پہچانتا ہے، سو ریلیز نوٹ ہاتھ سے لکھنے ہوں گے — نثری عنوانات سے وہ نہیں بنائے گا
